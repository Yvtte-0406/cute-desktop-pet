# 待确认方案：Windows日历设置与AI任务提醒

状态：Windows时间设置独立只读识别已尝试；尚未集成任务栏附加日历读取或AI调度。

此前实现只读取系统时钟与时区，以lunar-javascript计算农历节气，并内置2026年放假调休表；它没有读取Windows设置，现已移除。

建议的日历路线：先用Windows官方本地接口读取当前用户的时区、区域、日期格式和默认历法，尊重用户覆盖值；另行核验“在任务栏显示其他日历”的实际配置来源，因为任务栏附加日历与区域默认历法不能混为一谈。只读，不改变设置，不扫描个人文件，不使用截图OCR常驻监视桌面。设置发生变化时刷新。读取失败或接口不支持时明确标为不可用，不悄悄套用中文农历或固定年份数据。

官方接口中的历法类型与格式设置，不是通用的法定节假日/调休数据库，也不自动等同于任务栏界面展示内容。第一步验收应列出本机能读出的实际字段和无法提供的内容。若用户还需要节假日数据，必须另行确认可靠的数据来源或订阅，并显示来源及更新时间；不再把年度日期写死在程序中。不自动连接Outlook账户。

AI提醒建议：本地检查准确处理截止时间、剩余时间和可用时段；模型负责理解事项描述、比较优先级、解释为什么应当现在开始，并给出下一步行动和下一次评估时刻。模型不负责做时钟运算，也不能凭空断言任务已经开始、已完成或用户正在空闲。

建议增加可选“预计耗时”和“进度/剩余工作量”字段；用户未填时模型只能给出不确定估计，不应把“还剩2小时”简单等同于“紧急”。例如一份预计需要3小时、今晚截止的报告应优先于明天截止且只需10分钟的事项。未来可采用事件驱动的评估：新增或修改任务、ddl临近风险变化、用户暂缓/标记处理后重评估；后台本地计时负责在模型建议时刻唤醒，不通过频繁请求API轮询。

一期建议保留现有30分钟提醒，单独增加可选AI优先级建议，验证判断与打扰程度后再替换为动态提醒。第二期才由模型建议提醒时机，并加入“正在处理/稍后提醒”、免打扰时段、最短间隔及每日提醒上限。具体交互需用户确认，不在当前版本预先添加。

开销控制：新增/修改时先合并短时间内的连续编辑；只在相关任务状态或风险变化时调用，复用缓存结论；仅发送判断所需的任务文本、ddl、可选耗时/进度与必要时间上下文，不发送屏幕或文件。选低价模型，限制输入、输出长度、每日调用次数与月预算；所有自动重试同样计入预算，达到硬上限即停止联网，回退本地提醒。依据供应商实际用量和价格累计估算费用，不能仅靠提示词要求模型“少花钱”。

建议试运行上限：20次/日，月预算人民币5元或用户指定金额；这只是待确认配置，不是费用承诺，也未启用。最终需确定API供应商、模型和实际计费方式后计算。密钥应在本机受保护存储，不写进仓库。

已确认：先尝试系统时间设置只读识别，独立工具已完成。待确认：是否集成进桌宠、任务栏附加日历的可靠读取方式、AI先给优先级建议还是直接试动态提醒，以及API供应商和月预算。
